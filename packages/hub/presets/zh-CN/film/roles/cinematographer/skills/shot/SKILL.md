# 生成镜头

## 流程

1. 读输入：`shot_list`、`storyboard`、`style_guide`、出场人物的 `character`。抄下风格后缀、这场戏的场景后缀、每个人物的外观描述，以及风格指南里用户的硬性要求（出图出视频前对照检查）；用 `get_asset` 取得要用的分镜画面和参考图的文件路径。
2. 按依赖排序：没有"接尾帧"依赖的镜头可以一起提交，但先提交一两条，结果对了再提交其余。原因：平台对取消和计费的支持不同，先验证能减少批量返工；取消后是否真正停止、是否计费，以回执为准。
3. 为每个镜头写提示词（见下），用 `start_job` 提交给本片选定的出视频工具（`server` 和 `tool` 是它的工具服务名和工具名），按模型支持与实际计价选择的小样规格；没有更便宜档位时复用交付规格，不凭分辨率名称推断费用。
4. 用 `subscribe` 订阅这些后台任务，然后结束本轮：任务会保持开启，结果回来时接着做。回来后检查文件，不合格的调整后重拍（再提交、再 `subscribe`）。
5. 用 `put_asset` 把每个小样登记为 `shot/<镜号>`（`path` 指向视频文件），描述里写提示词与参数，并注明是小样。以交给导演审的内容结束本轮，写明这些小样；这个任务到此结束。
6. 小样达到交付规格且获准使用时，直接复用，不为改称“正式版”重复生成。需要升清时按所选模型能力：优先使用已通过视频的升清或编辑；只能重新生成时，保留原提示词与输入，说明人物和动作可能改变，作为新候选重新审查。登记同一个 `shot/<镜号>` 的新版本，说明处理方式。

## 提示词

写成连贯的一段话，不要堆关键词。顺序固定：

1. **主体**：人物的外观描述（原样复制）。用了参考图时写明对应关系（见下）。
2. **动作**：一个清楚的动作，写出起止和速度（"缓慢地从画面左侧走到窗前，停下，抬头"）。
3. **场景**：地点、时间、环境里看得见的东西。
4. **镜头**：景别、角度、运动（"中景，平视，镜头缓慢向前推"）。
5. **光线**：光从哪来、什么性质。
6. **声音**（有声镜头）：谁说什么，放在引号里；环境声是什么。
7. **场景后缀和风格后缀**（都原样复制，场景后缀在前）。

例：

> 三十岁的女性，齐肩黑发，脸型偏瘦，穿深灰色长风衣和白色衬衫，背一只褪色的墨绿帆布包（参考图 1）。她拖着行李箱从画面左侧小跑到售票亭窗前，停下，抬手敲了两下玻璃。深夜的渡口，江面有雾，售票亭亮着一盏昏黄的灯（场景参考图 2）。中景，平视，镜头固定。唯一的光源来自售票亭，暖光打在她的侧脸。她说："师傅，还有船吗？"环境声是远处的水声。写实电影质感，低调布光，钨丝灯暖光与青色阴影，浅景深，胶片颗粒，镜头运动缓慢稳定，色彩克制，画面无文字。

要点：

- **只写画面里有的东西**。模型不擅长理解"不要…"；想排除文字时写"画面无文字"。
- **一个镜头一个动作、一种镜头运动**。
- **用具体的词**：不写"很美的夜景"，写"雾中的江面，对岸一排模糊的橙色灯光"。
- **对白**：原话放进引号，写明谁说；一镜一人一句。无声镜头把 `audio` 设为 false，并且不要写任何台词。
- **画面里的文字**：需要时把确切的字放进引号并说明出现在哪。
- 一个镜头内需要变化时，优先让分镜师拆成两个镜头。一定要写在一条提示词里时，按工具说明里这个模型认的写法：有的版本只认"镜头1…，镜头2…"这样的序号，有的认整秒的时间段（"0–3 秒…，3–6 秒…"）。

## 参考图的写法

参考图按传入的顺序编号，提示词里怎么称呼它们，以出视频工具的说明为准。提示词里要**逐张说明借用什么**：人物、服装、场景，还是构图。只传图不说明，模型不知道怎么用。

## 五种生成方式对应的参数

参数名以出视频工具为准；下面用的是常见的叫法。

| 镜头表写的 | 参数 |
| - | - |
| 首帧 | `first_frame`：这个镜头的分镜画面 `frame/<镜号>`。提示词从这一帧之后发生的事写起，不必再描述画面里已有的构图 |
| 文生 | 只有 `prompt` |
| 参考图 | `reference_images`：人物参考图在前，场景参考图在后 |
| 接尾帧 | 上一镜提交时带 `last_frame_output: "shots/<上一镜号>_last.jpg"`（尾帧是 jpeg）；这一镜把它作为 `first_frame`。上一镜的结果里会写明尾帧有没有存下来，没存下来就不要用这个文件 |
| 首尾帧 | `first_frame` 和 `last_frame`：分镜师登记的 `frame/<镜号>` 和 `frame/<镜号>-尾` |

限制：哪些参数不能同时用、参考图最多几张、图片多大、接不接受带人脸的图，都随模型而定，写在出视频工具的说明里和所选模型的技能里，以那里为准。参考图够用就好：一个人物一张正面，再加一张场景，通常两三张。

## 其他参数

| 参数 | 用法 |
| - | - |
| `output` | `shots/<镜号>.mp4`，如 `shots/s03_02.mp4`；小样加 `_draft` |
| `duration` | 镜头表的时长（已含剪辑余量），不超过工具说明里的上限 |
| `ratio` | 全片统一，按简报的画幅 |
| `resolution` | 小样按支持档位、实际价格与检查需要选择；交付按简报；已有小样合格则复用 |
| `audio` | 有对白或需要现场声为 true；纯画面镜头为 false（由剪辑师处理声音） |

## 首帧与实测输出

提交前检查首帧的身份、手与道具的接触关系、动作起点和方向，与前后镜一致。首帧本身阻碍动作时先说明并请求上游调整，不靠堆叠提示词反复重拍。

输出用 `ffprobe` 核对实际宽高、时长、帧率及音轨；请求参数是目标，回执和文件才是结果。元数据符合也不证明动作、表演或声音可用；逐镜检查可用区间，结果注明未能验证的内容。把生成时长与剪辑使用时长分开记录。

## 自检（交付前逐镜看）

人物与定妆图一致；构图与分镜画面一致；动作完成且头尾有余量；没有肢体和面部的明显瑕疵；没有乱码文字；色调与相邻镜头接得上；有声镜头的对白内容正确。

重拍时**一次只改一处**，否则不知道是哪个改动起了作用。提交重拍前，把新旧两版提示词和参数对比一遍，确认你要改的那一处真的改了：脚本或文件名没跟着变，重拍出来还是原样，钱照花。同一个镜头三次仍不行，停下来，在结果里说明现象并建议怎么改镜头设计。

## 技术预检

导演在简报定稿后派来的技术预检：用一条小样验证本片实际依赖的能力。需要人物则测人物参考，需要对白则测口型与台词，需要动作或现场声则测对应内容；无人物、无对白的片子不额外加入。结果写明输入是否被接受、实际规格、动作与声音是否可用、缺少什么接入或授权，以及可核实的用量和金额；未知价格明确标注。

## 试拍

导演只派来两三个镜头并说明是试拍时：只出小样，不出正式版。结果里除了镜头本身，写清每个镜头生成了几次才得到可用的一版、每次失败的原因。导演据此估全片的成本。

## 结果里要写

每个镜头：镜号、资产 id、时长、是小样还是正式版、一共生成了几次；重拍过的写明原因和改了什么；没完成的写明卡在哪；取消过的任务及是否计费。
