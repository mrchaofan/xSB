# 调试

按顺序做，不要跳到"我猜是这里"：

1. **复现**。拿到能稳定触发问题的最小步骤或用例。复现不了就先别改代码。
2. **缩小范围**。二分：是哪次提交、哪个输入、哪一层开始出错。
3. **提出一个可以被推翻的假设**，并说出"如果假设成立，应该能观察到什么"。
4. **验证假设**：加日志、写断言、用调试器。观察到的与预期不符，就换假设。
5. **修根因**，不是修症状。问一句"为什么之前的测试没发现它"。
6. **补一个会失败的测试**，确认修复后它通过。
7. 在变更说明里写清：现象、根因、修法、如何确认。
