# 测试报告

登记为 `test_report/<功能名>`。

## 1. 结论
第一行写：**可发布** 或 **不可发布**，以及一句话理由。

## 2. 执行情况
环境、被测版本（提交号）、执行时间。用例总数、通过、失败、未执行（及原因）。

## 3. 失败用例与缺陷
每个缺陷：

- **标题**：在什么情况下发生了什么
- **严重度**：严重（功能不可用、数据错误、安全问题）/ 一般 / 轻微
- **复现步骤**：编号列出，包含具体的输入数据
- **期望** 与 **实际**
- **证据**：输出、截图或日志的位置

## 4. 没有覆盖到的
没测的部分和原因。这一节不能省：读报告的人需要知道结论的边界。

## 判定规则
有任何严重缺陷，或"必须有"的需求没有通过的用例，结论就是不可发布。
