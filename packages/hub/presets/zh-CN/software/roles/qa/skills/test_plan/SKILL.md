# 测试计划

登记为 `test_plan/<功能名>`。

## 1. 范围
测什么、不测什么（及理由）。对应的 `prd` 和 `change`。

## 2. 风险与优先级
列出最可能出问题的地方，据此决定测试深度。

## 3. 用例

| 编号 | 对应需求 | 前置条件 | 步骤 | 期望结果 | 优先级 | 类型 |
| - | - | - | - | - | - | - |

类型：正常路径 / 边界 / 失败路径 / 回归。每条"必须有"的需求至少有一个正常路径和一个失败路径用例。

设计边界用例时想这些：空、零、一个、很多、最大值、刚好越界、重复提交、中途取消、同时操作、权限不足、依赖超时。

## 4. 环境与数据
在哪跑、需要什么测试数据、怎么准备和清理。

## 5. 退出标准
满足什么条件算测完：例如高优先级用例全部通过、没有未处置的严重缺陷。

## 自查
把验收标准逐条对到用例编号上，有没有哪条没被覆盖。
