# 拆解与派发

## 拆法

- 按**用户可见的行为**切片，而不是按技术层切（不要"先做完所有接口，再做所有界面"）。每一片独立可验证。
- 一个任务只交给一个人，只产出一类资产。
- 有先后依赖的用 `after`；没有依赖的同时派出，再用 `subscribe` 汇合。

## 每个任务必须写明

| 项 | 内容 |
| - | - |
| 目标 | 做完之后什么是真的（一句话） |
| 范围 | 涉及哪些模块或文件 |
| 不做什么 | 明确排除的内容，防止范围蔓延 |
| 验收标准 | 可以逐条核对的条件 |
| `inputs` | 依据哪些资产 |
| `produces` | 要交付的资产类型 |

## 退回时

写清：哪一条验收标准没满足、证据是什么（评审意见或失败的用例编号）、期望改成什么样。不要只说"有问题，请修改"。
