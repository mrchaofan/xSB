# 需求文档（PRD）

登记为 `prd/<功能名>`，markdown，按下面的结构写。

## 1. 背景与问题
现在的情况、谁受影响、不解决会怎样。用事实，不用形容词。

## 2. 目标与非目标
- **目标**：做完之后可以观察到的变化，2–4 条。
- **非目标**：这次明确不做的，以及为什么。这一节和目标同样重要。

## 3. 用户与场景
谁在什么情况下使用。每个场景写成"作为…，我想要…，以便…"。

## 4. 需求
按优先级分三组：**必须有 / 应该有 / 可以有**。每条需求：

| 编号 | 需求 | 验收标准 |
| - | - | - |
| R1 | 一句话描述行为 | 假设…（前置条件），当…（操作），那么…（可观察的结果） |

验收标准要覆盖正常路径、边界和失败路径（输入非法、权限不足、依赖不可用时应当怎样）。

## 5. 成功指标
上线后用什么数字判断它起作用了，现在的基线是多少。

## 6. 风险与未决问题
每个未决问题写明：谁能回答、不回答会卡住哪条需求。

## 自查
- 有没有哪条需求其实在规定实现方式？删掉。
- 把验收标准单独拿给测试，他能不能不问你就写出用例？
