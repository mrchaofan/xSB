# 代码变更

## 步骤

1. 读输入资产，列出这次要满足的验收标准。
2. 读相关代码和测试，确认方案里的接口契约与现状对得上；对不上就停下来在结果里说明。
3. 先写或改测试，让它表达验收标准，再写实现。
4. 运行项目的测试、类型检查、lint。全部通过后再往下。
5. 自己读一遍 diff：有没有调试输出、无关改动、没用到的代码。
6. 写变更说明并登记为 `change/<功能名>`。

## 变更说明的结构

- **做了什么**：按行为描述，对应到 PRD 的需求编号。
- **为什么这样做**：与方案不一致的地方及原因。
- **涉及文件**：路径加一句话说明。
- **如何查看变更**：基准提交，以及看到这次 diff 的命令（如 `git diff <基准提交>`）。
- **如何验证**：运行了哪些命令，贴出真实的结果摘要（通过数、失败数）。
- **未做与已知问题**：范围内没完成的、范围外发现的、没有验证到的。没有就写"无"。

## 不要做

- 不要为了通过而改动无关的测试。
- 不要提交含密钥、令牌的内容。
- 不要引入新依赖而不说明理由。
