# 输入记录、ACP 回执与队首操作

2026-11-26。实现分支：codex/input-delivery。

## 目标与证据

Hub 持久记录用户提交；ACP v2 插入回执确认执行器会话接收。Claude Code 和 Codex app-server 是执行器，claude-agent-acp 和 codex-acp 是适配器。回执不保证会话已持久化或已向 LM 发送。允许 Hub 记录比 LM 最终看到的更多，用状态与删除线表达差异。

## 路由与保护

用户输入接收即保护当前 turn，保持一个 Agent 至多一个有效 turn。Agent 的普通输入向未保护 turn 插话，向受保护 turn 排队；按当前 turn.protected 判断，而非最初发起者。

每会话只有一批 prompt 等待插入回执。后续用户插话归当前 turn，立即保护，回执到达后立即接续，不等待 turn 完成。会话绑定、上下文恢复和停止隔离仍可暂时扣留。匿名回显只记原生插入位置；原响应或明确 Hub 消息 ID 回显才能确认具体批次。

Agent 调用工具返回受理状态和 ID，不默认把执行结果 prompt 回调用方。DAG 规则继续决定展开、依赖和终态；普通调用与工作流追加工作结果留在账本及节点视图。工作流完成、分支选择及升级控制通知按图规则处理。

## 持久事务

接收时将原文、邮件、账本及待送达历史统一提交。发送前持久记录 offered。插入确认与 user_message_chunk 统一提交；取消、失败和重启中断也与对应账本状态提交。提交成功后才通知客户端。消息使用稳定 ID，按 ID 去重，状态以追加事件更新；不修改旧 JSONL 行。

尚未准备发送的本地输入可以仅存内存；一旦 Hub 正式接收或排队，原文与状态必须可靠保存。消息在历史中的接受顺序稳定，真实原生插入位置另行关联记录，不能从回执 FIFO 猜测。

## 产品状态

| 内部事实 | 展示 | 操作 |
| --- | --- | --- |
| 尚在绑定或等待前一批回执 | 等待发送，浅色小字 | 尚未投递的插话可取消 |
| 已投递、无插入回执 | 发送中，浅色小字 | 不能作为排队输入撤回 |
| Hub 业务队列 | 排队中，浅色小字 | 取消；仅队首有立即发送 |
| 插入回执 | 正常显示，状态可称已送达 | 不称 LM 已看到 |
| 明确取消 | 删除线、已取消 | 保留原文 |
| 发送失败 | 删除线、发送失败 | 重新发送 |
| 重启或断线后未确认 | 删除线、发送中断 | 重新发送 |

删除线表示本次投递已经终结，不表示 LM 确定没收到。

## 队首控制

所有未投递的排队输入可以取消。立即发送只允许队首，提交点校验消息 ID、目标 turn、停止及 DAG 条件。用户点击授权该消息插入当前 turn，同时保护 turn，保留消息原始来源。

开始发送的队首仍占据顺序位置，至回执或明确终结前后续项不显示立即发送。输入已经发给执行器不能被取消排队。取消已排队任务遵循真实 parents 停止边并保留无关共享依赖；立即发送不能绕过依赖或停止隔离。

## 重启与重发

重启前没有回执的原输入统一按发送中断结算，清理旧邮件与 blocked 工作，绝不自动重投。失败输入不进入 owed 清单；旧 owed 数据不注入新请求。用户明确重新发送使用新 ID，旧条目保留。

已有插入回执保留其事实。执行器原会话按自身记录恢复；恢复失败写 not_restored 边界，不使用 Hub 历史或摘要补入旧用户消息。正常容量续接可继续使用已确认历史。

迟到真实回执只修正对应旧输入，不能恢复任务、改变新 turn 的权限或重新阻塞图。任务执行状态与输入送达状态分开。

## 验收

- 用户输入立即保护，串行回执不等待 turn 结束；输出与 idle 不代替回执。
- Agent 受保护路由、DAG 依赖和停止权限维持。
- 队首、非队首、并发点击、取消、在途占位及过期 turn 校验。
- 原文/邮件及插入/历史事务在任意记录间断电均可恢复完整。
- 重启不重投未确认、未提交和 blocked 工作，不能因依赖释放启动旧指令。
- 普通 Agent 与追加工作完成不自动回传结果 prompt。
- 失败保留原文，不自动补交；明确重发使用新消息 ID。
