# 会话与工作流

每次新建会话都会创建一个主 Agent。工作区可以保存多个主会话，它们各自拥有对话历史、模型后端和工作流，工作区共享同一份资产登记。询问、写作或单次创作直接在当前会话完成。需要并行工作、条件选择或多步交付时，主 Agent 才建图。

## 规划与执行

主 Agent 调用 `plan({graphJsonl})` 保存一个候选，替换之前的候选。候选供预览，现有活动图继续运行。不带参数调用 `execute({})` 采用本轮看到的候选，也可以调用 `execute({graphJsonl})` 直接采用完整图。版本名由宿主按会话顺序分配（`plan-1`、`plan-2`…，与资产版本 `v1` 区分），同一图定义始终得到同一版本名；模型不起名，也不传版本名，宿主按本轮实际展示过的候选核对。每个主会话最多有一个候选和一个活动版本，候选的规划依据发生变化后须重新规划。

主会话的 `[xSB workflow]` 上下文不是每轮都附：

- **上下文里没有图时附完整 JSONL**：首轮、后端压缩上下文之后（`compaction_update`，或用量回落）、换后端会话续接之后，附上活动图和候选图的完整 JSONL（与提交格式相同）。工作流结束后也一样。
- **模型自己得不到的变化立即附**：暂停、出错、用户停止丢掉的追加工作和通知。
- **工作流进行中每 10 轮附一次**（`WORKFLOW_REFRESH_TURNS`），只带状态和变化了的定义。节点完成、等待选择、上报都有各自的通知；采用、改图、追加是模型自己做的，它知道。
- **工作流结束后不再附**：到达终点，没有节点在工作、排队或等待选择，也没有候选。模型从对话历史里保持对它的感知。

全文随时可凭 `graphRef` 用 `read_context` 读取。主对话的消息只交给主 Agent，任务 Agent 收不到；上下文里只有工作流的状态和交付摘要，没有任务 Agent 的对话。

JSONL 中每个节点和每条边各占一行。任务节点支持 `input`、`model` 和结果的 JSON Schema `schema`。下面的审片图通过后直接汇总，需要修订时先执行修图。

```jsonl
{"node":"draw","prompt":"绘制并登记定妆图。"}
{"node":"review","prompt":"审查本次定妆图。"}
{"node":"fix","prompt":"按审片意见修订定妆图。"}
{"node":"approved","kind":"end"}
{"node":"revised","kind":"end"}
{"from":"draw","to":"review"}
{"from":"review","to":"approved","case":"pass"}
{"from":"review","to":"fix","case":"revise"}
{"from":"fix","to":"revised"}
```

普通边等待有效交付。条件边还等待针对该次交付的选择。单选须选一个已有选项，多选源加 `"multi":true`，允许 `choose({from,cases:[]})`。若所有条件入边均跳过，或全部入边均跳过，节点也跳过。其余节点等所有入边有结果。所有合法选路必须各自到达一个终点。校验总预算默认 100000，可在项目的 `.xsb2/config.json` 设置 `limits.workflowValidationSteps`。

## 改图与交付

- 单点改目标用 `execute({replaceNode:{node,prompt,input,…}})` 提交完整节点。保留同名同类型节点的会话和原边。调整依赖、增加或删除节点时提交完整图。
- 宿主在采用时撤销已经过期的工作与交付。依赖过期交付的下游重新等待，独立任务沿用同一次执行。删除后重建的同名节点获得新实例。
- 指派中包含本轮实际采用的全部前序摘要与资产版本，共同祖先只出现一次。直接前驱还可带结构化结果。任务 Agent 通过 `finish({summary,assets,result?})` 暂存交付，未产生文件时传空数组。该次执行正常结束且依据仍然有效时，宿主才接纳交付。
- 主 Agent 用 `prompt({node,text})` 派追加工作。每项沿用提出时的目标和素材线索，排队逐项处理，交付回到主对话。相同正文的两次独立调用会产生两项工作。传输层使用同一收据重投时返回原结果，跨连接重投使用相同的 MCP `_meta["dev.xsb/call-id"]`。

## 内置工具的感知

工作流工具由 xSB 通过名为 `workflow` 的 MCP 服务提供，代理程序里显示为 `mcp__workflow__<工具>` 或 `workflow.<工具>`。系统提示词的"Your tools"一节和这个 MCP 服务 `initialize` 返回的 `instructions` 都说明：这些就是用户所说的工作流、编排、拆分任务、"workflow 技能"，它们不是磁盘上的 skill 文件，也不需要安装。工具描述以 "xSB workflow:" 开头。

## 用户直接问任务 Agent

用户可以在任务会话里随时提问。任务 Agent 先给问题归类，再处理：

1. **和自己的任务有关**（目标、输入、素材、进度、交付）：自己处理。如果任务本身需要改变（交付内容、超出给定的输入或范围），调用 `escalate({message, pauseSelf: true})`，节点暂停，等主 Agent 决定，不悄悄改方向；当前交付需要作废时再加 `invalidateSelf`。
2. **和自己的任务无关，但和整体任务有关**（其他节点、计划、顺序、优先级、最终结果）：不自己处理，也不替主 Agent 回答。调用 `escalate({message})`，附上用户原话；节点照常工作。
3. **和两者都无关**：直接简短回答，不改动任何工作。

上报之后，任务 Agent 告诉用户主 Agent 会在主对话里处理。拿不准是第 1 类还是第 2 类时就上报，只有自己的任务必须改变时才暂停。

上报只有一个工具 `escalate`，两种情形的区别只在节点要不要停下来等。主会话收到通知 `{escalate, message, userSaid?, paused, invalidateSelf?}` 后，在主对话里回答用户，需要时用 `execute`（`replaceNode`）、`prompt`、`pause` 或 `resume` 调整工作流。`paused` 为真表示节点在等主 Agent：用 `execute({replaceNode})` 采用修改后的定义，或用 `resume({nodes:[该节点]})` 维持原任务。

## 向用户提问（ask）

主 Agent 和任务 Agent 都可以用 `ask` 问用户 1–4 个问题，每题是单选、多选或填空；单选和多选可以带 `other: true`，让用户另外填写。问题在对话里显示成一张卡片，Agent 显示"等你回答"。

`ask` 立即返回，Agent 随即结束这一轮。用户的回答就是他发给这个 Agent 的下一条消息，有三种：

- **提交**：模型收到每题的问题和答案，前面一句说明。
- **跳过**：模型收到"用户跳过"，自行决定并说明选了什么。
- **不回答、直接发消息**：问题结束，模型收到这条消息，前面说明用户没有回答。

工具调用不挂起等人：等待会超过代理程序的工具超时（codex 默认约 60 秒），也撑不过中枢重启；一条消息两者都不受影响。每个对话同时只有一个未答问题，新的提问替换旧的。

任务 Agent 在执行指派时提问：这一轮没调 `finish` 就结束，也不算未完成，工作保持进行、等待回答；回答所在的那一轮接续同一项工作，在其中 `finish`。回答若赶在提问那一轮结束前送到，会并入那一轮，那一轮仍须 `finish`。节点被暂停或中枢重启后，等待取消，之后的回答按普通插话处理。

## 插话、暂停与恢复

主会话可以直接回答无关问题。工作流进行中，桌面主输入框发出的消息针对当前工作流：模型收到时前面附一句说明，处理这条插话期间暂缓图的派发和接纳。工作流结束后，主对话的消息就是普通消息，不再附说明。任务会话默认针对当前工作或交付，选“仅询问历史”可单独讨论旧版本。工作流的 `pause` 和 `resume` 可传 `nodes` 指定范围。任务需要改向时调用 `escalate({message, pauseSelf: true, invalidateSelf?})`，主 Agent 采用修改，或用 `resume({nodes:[…]})` 沿用原目标。多个暂停来源分别生效。

插话只有进入模型的对话才生效：没有送达的插话（被拒、失败、过期）不挡住图，恢复时也不续做。已送达的插话所在那一轮失败或被停止后，视图会标出 `interrupted`，界面提供"继续"。用户停止清掉的追加工作和未送达的通知，会随下一份工作流上下文告诉主 Agent。正在执行的指派被改图撤销后，节点的下一份指派会写明旧的已作废；节点会话换了上下文后，续做时重新发送整份指派。通知没有送达时会自动重投，最多 3 次。

宿主重启时增加全图暂停。查看工作流和历史可以在暂停期间进行。明确恢复后，已结束的待接纳交付重新校验，执行中断的工作在原会话续做。终点汇总与追加结果通过持久化通知送回主会话。

## 资产

使用 `asset_put(name,path)` 登记文件，以回执中的名称和版本交付。`asset_version_get(name)` 查询当前版本，任务对底图的首次选择会随该工作持久化。`asset_list(name)` 列出可访问版本，`asset_get(name,version)` 读取指定版本。主 Agent 或追加工作可选回旧版或清空当前指针。操作当前指针不会触发工作流重算。

在桌面制品列表或预览中引用文件，会把可移除的引用插入所选主对话或任务对话的草稿。发送已登记制品时，宿主收到卡片对应的名称与固定版本。同一条消息可以包含 `<asset>{"name":"主角定妆图","version":"v1"}</asset>` 和修改原话。主 Agent 可把精确引用传入任务 input。未选定版本时传递原话和定位线索，由使用素材的任务 Agent 查询或向用户确认。
