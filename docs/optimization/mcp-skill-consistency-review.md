# 其余 MCP 与技能一致性核查

核查范围是 xSB 产品内置的 `team`、`browser`、`media` MCP，以及中英文 `software`、`film`、`film-ark` 预设，共 52 个 SKILL 文件。检查工具名称和 schema、技能输入合同、角色继承及能力说明，并对发现冲突的位置读取实现核实。没有扫描用户电脑上的全部第三方 MCP，也没有调用在线生成或生产资源。本次只新增核查报告，没有修改这些遗留规则。

## 整体结果

- `software`：每种语言 6 个角色、12 个技能；预设结构检查没有错误或警告。
- `film`：每种语言 6 个角色、13 个技能；中文结构检查通过，英文导演说明有过长警告（10,475 字符）。
- `film-ark`：每种语言 6 个角色、14 个技能；中文结构检查通过，英文导演说明有过长警告（11,676 字符）。
- 结构检查通过只能说明角色、资产类型和声明关系可解析，不能验证指令之间的语义一致性。前次优化覆盖了部分入口，尚未清除所有相关角色说明和其余技能里的旧规则。

## 确认的工具说明问题

### [P2] 媒体 MCP 引导调用不存在的 `await_tasks`

位置：`packages/media-mcp/src/server.ts:178`。

`generate_video` 的工具说明让角色用 `start_job` 提交后再用 `await_tasks` 收取结果。当前 `team` 的工具列表没有 `await_tasks`，已有的方式是后台结果唤醒及 `subscribe`。这是可以直接通过工具列表和源码确认的名称不一致，任何使用该内置视频工具的团队都可能受影响，不只 `film-ark`。

应在工具说明中明确提交、订阅和结束回合的实际流程，并与 hub 的系统说明保持一致。

### [P2] 把 seed 的重复性写成结果保证

位置：`packages/media-mcp/src/server.ts`，`generate_video` 的 `seed` 参数说明。

说明写成相同 seed、提示词和输入会重复结果；provider 的说明只表示部分版本支持 seed。支持这个参数也不自动证明画面或文件完全可复现。

当前未在线测试各模型的确定性，因此这是说明承诺超过已验证能力的问题。应将 seed 定位为所选模型支持时的随机性控制，只有模型明确保证且验证过时才承诺复现。

### 后台任务的接入边界需要明确

位置：`packages/hub/src/tools.ts`，`start_job`。

它只能调用角色配置的 MCP 服务器，不能直接包装后端自带的 Shell 工具或应用注入的 browser MCP。这是实现边界；schema 已说“角色的 MCP 服务”，但系统说明笼统写“渲染、生成、任何耗时调用”，可能引起误用。

应在公共说明中同时说明边界。支持用户提供技能或 CLI，不代表该路径自动获得 xSB 的 job、订阅和取消管理。

## 通用电影团队中的遗留冲突

### [P2] 审片仍强制低清小样后再出正式版

位置：`film/roles/director/skills/dailies-review/SKILL.md:6`，中英文相同。

它仍要求先看低分辨率小样，通过后再让摄影师出正式版，与已修改的 `shot` 技能“合格小样直接复用”冲突。触发场景是单一规格套餐，或小样本身已经满足交付要求；审片入口仍可能派发没有必要的新生成。

应将审查通过与是否需要升清分开，根据实际素材规格决定复用、处理或重新生成。

### [P2] 剧本、分镜与动态分镜仍套固定时长

位置：

- `film/roles/screenwriter/skills/script/SKILL.md`：超过 15 秒的连续动作必须拆开。
- `film/roles/storyboard-artist/instructions.md`：单镜通常 4–15 秒，每镜留 1–2 秒。
- `film/roles/editor/skills/animatic/SKILL.md:31`：动态分镜每镜通常减 1–2 秒。

这不能统一适用于长镜头、支持更长生成的模型或亚秒级动作剪辑。动态分镜前面又说按镜头表时长排列，后面建议统一减秒，时长语义不够明确。例如预计成片使用 0.8 秒的动作镜头，不能机械减去 1 秒。

应分别记录成片使用时长、源素材生成时长和剪辑余量，按模型能力与具体动作确定。不要把一组经验数值当成全体用户的规则。

### [P2] 角色说明继续要求重复选角和出大图

位置：`film/roles/art-director/instructions.md:6`、`:9`，以及 `film/roles/storyboard-artist/instructions.md`。

美术仍要求主要人物先出三到五个候选、草图选定后再出定稿；分镜也要求首帧通过后再生成与视频分辨率相当的图。它们与已优化的 `casting`、`reference-image` 及导演复用原则没有完全对齐。

用户已有可用形象、只要求一个造型，或现有图已经符合首帧输入要求时，应复用。视频输出分辨率也不能直接替代首帧输入尺寸要求。

### [P2] 缺镜头时，剪辑和审剪辑给出相反指令

位置：`film/roles/editor/skills/cut/SKILL.md:10` 与 `film/roles/director/skills/cut-review/SKILL.md`。

`cut` 要求缺失镜头自动用占位顶替；`cut-review` 要求现在补拍，不让剪辑用别的镜头顶替。两者缺少粗剪与最终交付的条件区别。前者可能让不完整素材直接进入成片，后者可能阻止用户已经允许的占位粗剪。

应由任务明确是否允许占位；允许时标记并列出，最终交付是否可以含占位另行依据用户要求判定。`cut-review` 的固定轮次“不要跳”也应与用户提供已有导演版、允许直接修改的场景对齐。

### [P2] 剪辑仍把固定声音来源和感知能力当作通用边界

位置：`film/roles/editor/skills/cut/SKILL.md:43`、`film/roles/editor/instructions.md:7`，以及 `hub/src/prompts.ts` 的 `WORKING_RULES`。

剪辑技能写“这支剧组不生成配乐和旁白”，公共规则与剪辑说明将听音、实时观看一概留给用户。当前不同后端或自定义 MCP 可能有不同的媒体能力，因此应依据实际提供的工具判断；同时不能将存在音轨、抽帧或能打开播放器当作已经听过或看过。

应报告实际执行的检查、所用能力与未验证项。音频来源可来自用户文件、已有资产或实际配置的生成工具。

### [P2] 直接生图与 `cancel_task` 的要求没有对应取消句柄

位置：`film/roles/art-director/instructions.md:8`、`:11`；对照 `team/cancel_task` 和 `media/generate_image`。

美术说明建议直接调用生图工具，却要求停止时使用 `cancel_task`。直接 MCP 生图调用并不会获得一个独立的 xSB job id；`cancel_task` 接受的是调用者派出的任务或启动的 job，不能直接拿它取消任意平台生成 id。

需要区分 xSB task/job、同步 MCP 调用及平台任务：通过各自支持的取消路径操作，并确认平台结果。不能把取消等待、终止进程、停止生成和停止计费说成同一件事。

## 软件团队的问题与通过项

### [P2] 小改动跳步与技能输入合同不一致

技术负责人说明允许小改动跳过 `prd` 和 `architecture`；但 `change` 声明 `inputs: prd, architecture`，`review` 声明 `inputs: prd, architecture, change`，测试报告也需要 `prd`。

hub 的 `contractNote` 在缺输入时只给提示，不会拒绝派单。因此这是工作流说明冲突，不是所有小改动必然被系统硬性阻断。接收者可能停下补文档、重复询问，或在缺少明确验收标准时自行推断。

应定义小改动如何携带同等的目标、范围、验收标准和设计依据，并让上下游技能一致；无需为纯文案修改强制生成整套大文档。

### [P2] 验证要求没有说明不存在的检查如何处理

开发说明要求每小步运行测试、类型检查、lint；`change` 技能要求先写测试，再运行全部检查。触发场景包括纯资产修改、没有 lint/typecheck 的项目或缺乏测试框架的仓库。

应运行与改动相称且项目实际提供的检查；缺少必要验证时说明影响，不能虚构通过，也不能仅因不存在一个检查命令就把所有项目判断成失败。

### 未发现过时工具名的部分

- 软件团队使用的 `dispatch_task`、`after`、`inputs`、`produces`、`deliveryPref`、`subscribe` 与当前工具 schema 对应。
- 评审、QA 的核心要求仍是依据需求、可复现步骤和证据；它们并未声明固定生图或视频模型。
- browser MCP 的 7 个工具名称和当前实现对应：navigate、snapshot、click、type、press_key、back、screenshot。
- QA 说明中该内置浏览器缺少文件上传、多标签操作、悬停和拖拽的限制与当前工具列表吻合。分页快照继续复用同一次捕获的内容及元素编号，也与说明一致。此次没有进行真实网页交互或验证全部第三方浏览器工具。

## 优先级与验证边界

优先处理不存在的工具名、上下游合同冲突和重复生成指令；随后统一时长语义、能力边界与取消路径。英文导演说明的过长警告应通过减少重复和移出条件性细节解决，而非提高长度阈值。

本次运行了预设解析及 `check` 结构检查，并对工具名称、参数和实现做静态核对。没有新增行为测试，因为没有修改实现；也没有证明这些提示词问题在每个模型上必然触发。平台政策、精确模型上限、seed 确定性、计费和取消需要对应接入的独立验证。
