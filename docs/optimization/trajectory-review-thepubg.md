## 轨迹支持的技能改进

### 1. 先识别任务是在选身份还是选造型

`t_e6b4aab1a094` 要求为已指定的五位真人制作造型候选，变化衣服与发型整理，保留本人长相。旧 `casting` 技能却同时规定“用户给照片就不出候选”和“候选脸型、年龄感必须不同”。这会让同一技能在真人造型、虚构人物选角之间产生冲突。

已改为按任务分支：身份未定时选演员身份，身份已定时只变化用户要求的造型维度；已有选定形象且无需候选时直接进入人物设定。比较图排列已有原图，避免为比较重新生成脸；身份已定的人物不因容易混淆就换人。

### 2. 把参考用途与审批状态分开

`t_6e37fe7ba70a` 的核查结果指出，一张旧候选副本与已登记图片哈希一致，却曾被当作来源未明、不能参考。它是否是当前定稿，与它是否可以用于参考，是两件事。

`t_b1c65f0f2c35` 的结果还明确记录：借用另一人物持枪图时带偏了当前人物的脸，随后改用独立枪械参考。这支持按身份、服装、道具、姿态、场景分别说明输入用途；不能只列“图一、图二”。

已在 `reference-image` 中加入用途映射、独立道具参考、实际多图输入及副本去重原则。已获准或来源已核定的旧图可继续参考；真实平台限制需要具体证据。

### 3. 已选基准需要显式版本，输出版本由系统分配

美术会话第 5879、5911 行对应用户“直接使用上一版”“四张都”；导演会话第 2767 行要求沿用美术定稿并推进。旧导演说明要求派单“不写死版本号”，会把用户选中的旧版重新解释成最新生成版。

已改为在派单和人物设定中明确基准资产与版本，更新参考索引、固定描述和受影响的下游镜头。新输出仍由 `put_asset` 分配版本。冻结已通过部分，返修只处理实际需要改变的内容。

这次没有新增资产审批状态数据库。当前选定版本仍依赖设定表与任务输入表达，属于后续可改进的产品机制。

### 4. 首帧要支持动作，而不仅是合格静帧

分镜会话第 1307 行记录用户要求撤掉会把取景往上带的人物参考；导演第 4070 行指出拿枪姿势不自然并要求改变枪方向。局部修好握持又可能影响下一镜的方向与轴线。

已在 `storyboard` 和 `shot` 中加入动作起点、手与可操作部位、接触/释放、运动路径和前后镜连续性检查。返修同时验收保留项与改变项。首帧本身阻碍动作时反馈上游，避免靠增加提示词反复重拍。

规则使用一般人物和物体关系，没有写入本片人物、枪械型号、座位关系或固定画幅。

### 5. 流程和规格依据能力、任务与既有授权

旧流程强制所有预检包含人脸和对白；所有小样取最低分辨率；正式版用相同提示词重新生成。这些规则无法覆盖无人物影片、无对白动作片、最低档并不便宜的套餐，以及已经达到交付规格的小样。

已改为预检覆盖本片关键不确定性，复用仍适用的实测结论；小样按支持档位、价格和检查需要选择。合格小样直接复用；升清优先处理已通过视频，重新生成仍须作为新候选审查。实际时长、画幅、帧率和音轨用文件验证，生成时长与剪辑使用时长分开。

简报按叙事节奏和模型时长估算规模，去除固定每镜秒数。已有授权覆盖后续工作时继续推进；金额未知、明确不设上限和免费分别记录。声音来源依据当前工具能力，不把某团队缺少配乐工具泛化成所有模型的限制。

## 已确认并修复的问题

### [P1] 交接遗漏只通过更新事件报告的工具活动

位置：`packages/hub/src/transcript.ts`，`turnsSinceCleared`。

现存轨迹的工具活动使用 `tool_call_update`。旧实现只处理 `tool_call`，会在换后端或更新会话时遗漏工具执行摘要；没有 messageId 的答复还可能跨工具活动拼接。完整 `agent_message` 形式也没有被读取。

已兼容两种工具事件并按每回合的 toolCallId 合并标题，工具边界重置答复聚合，支持完整消息形式。测试覆盖更新事件、重复生命周期、不同回合复用 id、插话及清空边界。修复前测试失败，修复后通过。

工具摘要说明调用发生过，不代表工具成功或语义质量合格；完整诊断仍需读原始记录。

### [P1] 超长最新回合被整段丢弃，交接误称没有历史

位置：`packages/hub/src/prompts.ts`，`handoff`。

摄影现存会话第 630 行的一条输入为 41,310 字符，已超过交接的 40,000 字符历史预算。旧实现遇到装不下的最新回合立即退出；没有其他已收录回合时写“没有历史对话”。即使该回合的最终答复很短，也会一起丢失。

已在全文装不下时保留该回合的输入、工具与答复摘要，明确标记 Excerpt；工具标题中的完整脚本压为一行。历史预算保持 40,000 字符。新回归样例修复前失败，修复后保留最近决定和答复。

摘要仍不能保证保留长文本中的全部约束，模型应按交接提示查询原记录及当前资产；这不是完整的长期决策存储方案。

### [P2] 角色说明要求不存在的 `parallel` 派单参数

位置：通用电影导演 `instructions.md`，对照 `packages/hub/src/tools.ts` 的 `dispatch_task` schema。

派单工具没有 `parallel`，同一角色目前在主会话中逐轮工作。旧说明会制造“已并行”的错误预期。

已改为场次拆单、`after` 依赖、`subscribe` 合并结果及 `deliveryPref`；独立生成由摄影师通过 `start_job` 提交。没有为配合文案增加新的并行会话架构。

## 待进一步复现的风险

| 风险 | 证据与触发条件 | 当前判断与建议 |
| - | - | - |
| 自定义工具的业务失败被任务标成 completed | ThePUBG 的 Seedream 包装器返回 `status: error` 的普通对象；`Jobs.run` 以 MCP 信封的 `isError` 决定失败 | 条件风险：若 MCP 包装未设置 `isError`，JSON 业务错误会被当成成功。本次留存的 72 个工具任务未发现可直接对应的错误 JSON。应验证接入端错误信封，不能让 hub 猜所有第三方的 `status` 字段 |
| 取消等待后收费子进程继续运行 | 项目 Seedream 包装器使用 `asyncio.create_subprocess_exec`，缺少取消分支的子进程回收；hub 取消先通知 MCP，超时再停止服务器 | 项目接入风险，尚未实测平台取消；停止等待、停止进程、停止平台任务、停止计费分别验证。不能承诺取消必然不收费 |
| 调试环境中的未处理动态 import 异常 | hub.log 第 1770 行 `ERR_VM_DYNAMIC_IMPORT_CALLBACK_MISSING`，堆栈为匿名 Timeout，前后有调试器连接 | 已有异常事实，但没有定位到 xSB 业务源码；当前相关源码未找到对应 VM 动态 import。应保存调试来源与复现方式，暂不归因产品运行路径 |
| 已复制到项目的角色不会自动获得预设改进 | ThePUBG 有自己的美术、摄影、分镜角色及技能；`loadRole` 对项目角色采用整份覆盖 | 这是现有设计。强行覆盖会破坏其他用户的定制。后续可提供预设版本差异与选择性同步，而非静默迁移所有项目 |

旧记录里出现的工具“不在当前工作中可用”也需要结合版本分析：当前能力实现已列出所有工具，并在调用时请求权限或说明拒绝原因。仅凭旧报错不能声称当前工具发现仍然失效。

## 泛化审查与后续方向

本次中英文同步修改 6 个技能：`brief`、`casting`、`character`、`reference-image`、`storyboard`、`shot`，以及导演说明。保留现有 `produces`/`inputs` 合同，模型数值上限仍由接入说明提供。

按以下场景检查规则适用性（为静态审查，未进行收费生成或独立代理行为评测）：

| 场景 | 应有行为 |
| - | - |
| 虚构人物、身份未定 | 可选不同身份候选 |
| 真人身份已定、要服装候选 | 保留身份，变化造型 |
| 已提供可用定稿 | 复用，不补做选角仪式 |
| 风景影片、无对白 | 测实际依赖能力，不加入人脸和对白 |
| 单一价格/单一规格套餐 | 不虚构降清节省，合格素材复用 |
| 用户选旧版、最新版本未通过 | 明确引用选中版本 |
| 用户要求局部改动 | 检查保留项和相邻镜连续性 |
| 用户明确不设费用上限 | 记录授权，仍如实报告未知成本 |
| 切换后端、最近输入超长 | 交接保留摘要，指向原记录和当前资产 |

后续优先考虑可持久化的“选定资产版本、依据、影响范围”记录，以及自定义接入的错误与取消合同验证。两者都比继续积累本片专用提示词更能减少跨项目返工。收益应通过重复生成次数、已通过资产返工率、决策恢复正确率和用户重复确认次数衡量，不能仅以单张图更漂亮或上下文更短为目标。
