# Turn 的投递、抢占和停止

本规则由 `kernel.ts`、`delivery.ts`、`session.ts` 实现，回归用例在 `packages/hub/test/turns.test.ts`。任务 ID 表示委托的工作，turn ID 表示某一次执行；等待子任务的工作可能跨多个 turn。

## 投递

每个 turn 有唯一 ID 和保护状态。用户发起的 turn 默认受保护；用户插话在接受时立即保护当前 turn，不等待后端插入回执。保护仅限制抢占，显式取消仍可停止它。

普通 Agent 投递在空闲时开新 turn，忙时排队。`dispatch_task` 的 `onBusy: "replace"` 必须同时带上 `target_turn_id`，来自 `list_agents` 的 `current_turn_id`。运行时在提交前检查目标 ID、保护状态、任务发起方和新任务是否可以运行；检查失败时，新任务仍按普通排队处理。权限等待前获取的 ID 不会被自动换成后来的 ID。停止 hook 中同步接受用户插话，也会使抢占失效。

成功抢占后，新任务先执行；旧 turn 未读的普通插话按接受顺序整批恢复到队头，先于更早排队的其他任务。抢占提交之后接受的用户输入加入抢占者的新 turn，并保护它。

`append_instruction` 是独立操作，必须指定 `target_turn_id`。权限检查、实际投递时都不能将失效目标替换为另一个 turn。目标结束前没有读到的追加指令被丢弃，不成为后续 turn。

## 停止

用户停止会话时，撤销已接受的当前工作和队列，丢弃未读用户输入，并停止相关下游工作。停止后接受的输入属于新工作。

Agent 显式取消按任务 ID 定位，发送给执行器的停止事件另带提交时的 turn ID。执行器校验 ID；停止确认也必须匹配所等的 turn，旧确认不能结算新停止。

停止先在同一事务中记录任务的 `stopping` 状态和撤回待办，再由 hook 发送后端取消。旧执行器创建子任务或后台 job 时读取已提交状态，不依赖 hook 是否已经运行。创建裁决之后、提交之前再检查父任务，防止裁决中的停止使新任务脱离调用关系。

级联沿持久化的 `parents` 边遍历，穿过已完成节点，并撤回未运行的后代。停止已经完成的根任务时，保留其原有状态和结果，以 `cascadeStopped` 标记剩余工作已经被撤销。共享任务仍按任务图的支撑者规则处理：还有其他未停止的支撑者时保留，全部支撑者被停止后撤销。整个撤销集先算完，再放行依赖。

## 后端边界

输入是否进入模型会话，以后端插入回执或输入回显为准。停止确认在仍有未结算的 `session/prompt` 回执时等待；最多等待 10 秒，超时关闭旧后端并撤销工具桥。

恢复的输入使用新运行时对象，旧请求的迟到回调不能确认它。携带 `dev.xsb/turn.id` 或 origin `turnId` 的通知按 turn ID 校验。普通 ACP 后端不必支持该扩展，因此停止后会退休旧后端会话、撤销其工具桥，新 turn 在新后端会话中通过历史摘要接续。旧会话的通知不能写入新 turn；历史作为上下文，不触发重新执行。该交接以 `stopped` 边界标记。

这些规则保证状态安全和停止传播；排队任务最终执行仍依赖公平调度和前序工作的结束。
