## 一、判定标准

用户看到的每一条输入，任何时刻都恰好处于下面三态之一，界面按态显示，状态只由**插入回执**推进：

| 态 | 含义 | 界面 |
| --- | --- | --- |
| 已看到 | 后端确认收进对话（`receipt(true)`，ledger `inserted`/`seen`） | 正常显示 |
| 在途 | 中枢已接收、尚未插入（mail 在盘，ledger `inboxed`/`queued`/`submitted`） | 显示为"待送达"，重启后仍可见 |
| 未看到 | 不会再以这条消息的身份进入对话（ledger `discarded_unseen`） | 原地标"模型未看到"并写明原因，不删除；若之后随别的消息补交，再标"已补交" |

另有两条：

- **幂等**：同一 messageId 至多插入一次；重试只能沿用原 id（或带原 id 的补交记录），由回执判定。
- **变形可见**：模型收到的与用户看到的内容不同（图片被替换、超长被截、附加作用域说明）时，界面标出。

## 三、问题按严重度

**P0：会重复，或模型静默漏掉**

1. 连接断开或崩溃后用户重发 → 重复。桌面端每次发送都生成新 id，中枢也不按 id 去重。
2. 桌面端重启后看不到在途消息 → 用户重发 → 重复。
3. 失败而被丢弃的用户输入永不再交给模型，`xsb.send` 还被吞成成功。
4. `workflows.restart` 直接 ack 已插入的邮件，并扣留主会话的全部邮件（D 表的两行 ✗）。
5. 插话记录不随回执结算：图卡住，resume 后把"未看到"的原文再发一次。

**P1：可见性错误（原文被删，或静默清空）**

6. 否决、目标过期、节点删除、用户停止撤回、abandon 这几条路径不写 Discarded；桌面端遇到 reject 就删除 pending。
7. 通知投递失败后不自动重投；Esc 时清空 outbox 和 extras 不留痕迹，主模型也不知情。
8. 中枢关闭期间的 discard 与契约矛盾。

**P2：变形与上下文**

9. 图片降级、超长截断、首条插话缺作用域说明，都没有标注。
10. 撤销的指派没有告诉节点模型；后端会话重建后，`work.inserted` 不复位。

## 四、建议的统一做法

1. **一个 id 贯穿始终。** 桌面端为每条输入生成 messageId，并和草稿一起持久化。重试一律沿用原 id。中枢在 `session/prompt` 入口按 id 去重：
   - 已在途：等待它的回执；
   - 已插入：直接返回成功；
   - 已是未看到：返回该状态，不再投一份。

   这一条解决 P0-1，也覆盖"后端已收、回执未落盘"之外的所有重试。
2. **在途可见，并且持久。** 新增按会话列出在途用户消息的查询（来自 mail + ledger）。桌面端启动和重连时用它补画"待送达"条目，并订阅账本更新来推进状态。解决 P0-2 和"无法知道模型看到了什么"。
3. **任何终止都写 Discarded，桌面端从不删除。** 中枢在否决、drop、withdraw、abandon 时，凡是用户来源的输入都补写 Discarded（附原因）。桌面端把 reject 改成原地标"未看到"加原因，不调用 `drop`，也不再把内容塞回输入框（避免换 id 重发）。整条"重发"改为在该条目上点"重新发送"，沿用原 id 走第 1 条的去重。解决 P0-3 的界面一半和 P1-6。
4. **失败的用户输入补交给模型（与第 3 条二选一，或同时提供）。** 非停止原因被丢弃的用户输入记入会话的持久"欠交"清单（只存 id，内容取自 mail 或记录）。下一个用户 turn 的首个请求在前面带一段"以下消息此前未送达"，拿到插入回执后才清账，被拒就还回去（与 `contextHandoffPending` 的先例相同）。同时写一条"已随 X 补交"的记录，桌面端把对应条目从"未看到"改为"已补交"。解决 P0-3 的模型一半。
5. **工作流重启统一走 `kernel.resume`。** `restart` 只扣留插话列表里的 id 和节点会话的邮件；已插入的交给 `kernel.resume` 处理（写说明、让任务失败）。解决 P0-4。
6. **插话记录以回执结算。** 插入回执到达时登记；被丢弃时删除。被插话阻塞单独作为一种状态显示，并给出恢复入口。解决 P0-5。
7. **工作流的待办撤销要通知。** 通知在 ledger 为未看到、且邮件已不存在时自动换 noticeAttempt 重投。Esc 或实例替换清掉 outbox 和 extras 时，向主会话写一条持久说明。halt 正在执行的 attempt 时，给节点会话写系统说明。解决 P1-7 和 P2-10。
8. **变形打标。** 输入记录附带 `delivered` 元数据（图片已降级、正文已截断并附文件路径、附加了作用域说明），桌面端在条目上标出。解决 P2-9。

改动面：协议（Discarded 增加原因字段、补交记录、在途查询、`delivered` 元数据）；hub 的 acp-server、delivery、kernel、session、workflows；桌面端的 workspace（send、pending、drop）和 renderer（条目状态与"重新发送"）。需要同步 docs/TURN-LIFECYCLE.md 第 4 节、WORKFLOWS.md 和 `prompts.ts` 的 `TASK_LIFECYCLE_RULES`，并在 turns.test、stop.test、kernel.test、e2e 中补上对应场景。

## 五、需要决定
